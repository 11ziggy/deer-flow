# DeerFlow 项目定位说明

## 一句话定位

DeerFlow 是一个面向复杂、多步骤任务的 Super Agent Harness。它把大语言模型、工具、上下文、运行状态和执行环境组织在一起，为开发者提供可直接使用、也可以扩展的 Agent 运行基础设施。

## 它解决的问题

大语言模型擅长理解自然语言、处理模糊信息、规划和生成内容，但模型输出具有概率性：它可能产生错误事实、选错工具、提供无效参数，或者在没有实际操作的情况下声称任务已经完成。因此，一次模型调用并不等于一个可靠的 AI 应用。

DeerFlow 的基本思路可以概括为“概率模型 + 确定性工程外壳”。模型负责理解目标、分析信息和提出下一步行动；Harness 负责组织上下文、管理状态、校验并执行工具请求，以及实施权限、超时、预算、错误处理和运行观测。Harness 不会消除模型的不确定性，而是限制、记录和评估这种不确定性。

## 核心能力

DeerFlow 基于 LangGraph 和 LangChain 构建。它通过 Prompt 和按需加载的 Skills 为模型提供当前任务所需的上下文；通过 Tools 连接网页、文件、命令和 MCP 等外部能力；通过 Memory、会话状态与上下文压缩支持多步骤任务；通过 Workflow 和 Sub-agents 组织复杂任务；通过 Runtime、Sandbox 和文件系统控制真实执行，并生成可交付的 Artifact。

模型只生成工具调用请求，真正的校验与执行由 Runtime 和 Tool 完成。任务结束后，还需要 Eval 从最终回答、实际产出和执行过程三个层面检查结果，例如确认文件是否存在、测试是否通过、结论是否有证据，以及运行过程是否越权。

## 一次任务如何运行

以“分析代码仓库最近一次提交的影响，运行相关测试，并生成 Markdown 报告”为例：

1. 用户向 Agent 提交目标和交付要求。
2. Harness 组装历史上下文、工具说明、Skill 和行为约束，并交给模型。
3. 模型分析任务，生成读取 Git Diff 或仓库文件的工具请求。
4. Runtime 检查工具权限、参数和路径，在受控环境中执行工具，再把真实结果反馈给模型。
5. “模型请求—工具执行—结果反馈”可以循环多次；Runtime 同时限制时间、Token 和最大步骤数，并记录状态。
6. Agent 生成报告后，Eval 检查 Artifact、测试退出码、证据和执行轨迹，再向用户交付结果。

模型负责难以提前穷举的语义判断，系统负责准入、执行、停止、留痕和验收。

## 它不是什么

DeerFlow 不是大语言模型本身，也不只是一个聊天界面。它不能保证模型永远正确，更不表示 Agent 可以绕过权限操作外部系统。对于输入稳定、步骤固定、规则能够穷举的任务，普通程序或确定性 Workflow 往往更容易验证，不必强行使用自主 Agent。

## 为什么适合作为 AI 应用工程学习项目

DeerFlow 展示了 AI 应用如何从一次模型调用扩展成完整系统。沿着它的真实请求链路，可以继续学习消息与状态、Tool、Sandbox、Skill、MCP、Sub-agent、Memory、流式协议、Checkpoint、恢复、幂等、安全和 Eval，并通过代码、测试和故障实验理解每项机制解决的工程问题。
